# 科研工作流 SOP 与成果案例

> 参照对象：立理 S1 官网 `https://s1.liliai.cn/#workflows`（工作流）与 `#cases`（使用案例）
> 数据出处：本机 `growth-workbench/data/workbench.db`，2026-11-11 只读查询，**未改动任何业务数据**
> 文档性质：设计稿 + 真实成果列举。凡标「已有」的均为当前代码/库里真实存在的能力，凡标「建议」的均为待落地项，不把设计说成已实现。

---

## 0. 结论先行

S1 值得参照的不是页面视觉，是三件事：

1. **工作流 = 可执行 SOP**：每条工作流定义「完整执行路径 + 验证标准」，用户只给研究目标/参数，系统自动选择并调用 Skills，产出可复现结果。
2. **图工程**：节点可循环、可回退到指定节点重跑、已验证结果保留；执行智能体与评审智能体相互独立，降低自我确认带来的错误。
3. **案例 = 证据链**：不只展示结论，还展示执行过程、产物文件与完整会话，并标出领域、运行时长、轮次。

对照下来，我们**底座已有约八成**：画布就是图工程（节点 input/prompt/skill/tool/output、`{{upstream}}`、run 支持单节点重跑）、技能库 registry.json 15 条 + 科研技能 presets 就是 Skills、论文 7 阶段与阻塞红警就是门禁、rchat 深度检索走 OpenAlex 真实入库并带引用、canvas 的「验论证 + 模拟审」就是独立评审、`chat_messages`/`canvas_node_outputs`/`llm_usage` 就是过程留痕。

**缺的是「显式封装 + 对外展示证据链」**：能力散在各页面里，没有一条具名工作流把「输入参数 → 节点链 → 验证标准 → 产物」写清楚，也没有一个页面把「用本工具做出来的成果」按证据链摆出来。

## 2. 我们的 6 条工作流 SOP（参照 S1 workflows 卡片格式）

卡片口径：`名称 / 分类 / 输入参数 / 提示预览 / 执行路径 / 搭配技能 / 验证标准 / 产物`。

### WF-01 深度文献调研与证据表 · 文献与研究（已有）

- **输入参数**：`研究问题`（必填）、`检索词组`（可选，后端自动扩展）、`能力标签`（深度检索 / 文献检索 / 报告撰写）
- **提示预览**：`请围绕 {研究问题} 做系统检索。(1) 多组查询词并行检索；(2) 结果去重并按被引/年份排序；(3) 关键结论逐条标注来源；(4) 输出研究脉络与空白；(5) 生成带引用的报告。`
- **执行路径**：`/`（工作台·调研模式）→ `/research` rchat → `POST /rchat/{sid}/stream` (deep) → `server/openalex.py` → 文献入库 → `report` 模式生成带引用报告
- **搭配技能**：科研技能 presets（内置注入 system）、可选本机/GitHub 技能
- **验证标准**：每条结论必须挂 OpenAlex ID / DOI；无引用不进报告；429 给「去设置填 key」引导而非无脑重试；报告 `meta.citations` 可回查
- **产物**：带引用报告（markdown）+ 入库文献 + 检索 queries/suggests 留痕

### WF-02 文献矩阵 → 研究空白 → 创新点 · 选题（已有）

- **输入参数**：`文献集合`（按 idea_id / 标签 / 手动勾选）、`对比维度`（如 是否开源 / 评测集 / 是否需要人工）
- **提示预览**：`基于所选文献，按 {维度} 构建对比矩阵，逐行提炼未覆盖组合，输出可检验的研究空白，再把每个空白转成带四维评分的创新点。`
- **执行路径**：`/literature` → `lit_matrix` → `POST /literature/{id}/painpoints` → `POST /painpoints/{id}/to-idea` → `ideas` 表
- **搭配技能**：`literature-survey-skill`、痛点结构化提示
- **验证标准**：创新点必须带 `novelty / feasibility / impact / effort` 四维评分；状态走 `captured → screening → selected / validated` 门禁；未评分不得进实验
- **产物**：120 条量级的文献矩阵行、创新点卡片、可追溯到文献的痛点

### WF-03 创新点 → 可证伪实验假设 · 实验设计（已有）

- **输入参数**：`创新点 id`、`基线方法`、`判据指标`
- **提示预览**：`把 {创新点} 转成一个可证伪假设：写明对照组、单一变量、成功判据与失败判据，并绑定实验实体。`
- **执行路径**：`POST /ideas/{id}/to-experiment` → `experiments` 实体 → `/experiments` Agent 对话（ChatPanel 版式对齐）
- **搭配技能**：实验设计提示、`academic-research-suite`
- **验证标准**：假设必须写明「什么结果算推翻」；实验必须 `idea_id` 可追溯；状态 `planned → running → analyzing → done` 流转才加分
- **产物**：实验实体 + 可追溯假设 + 配置快照

### WF-04 论文流水线：定框架 → 找空白 → 验论证 → 模拟审 · 学术写作（**已真实跑通，案例主角**）

- **输入参数**：`选题一句话`（如 `ai生成python单元测试`）、`约束`（1–3 个月 / 单机可跑）
- **提示预览**：`在 {约束} 下给出 3 个候选研究问题 → 梳理领域脉络与 Related Work 提纲 → 审查动机→方法→结果→结论链条 → 以审稿人视角给出接受/拒稿判断。`
- **执行路径**：`/canvas` → 画布 8「AI生成单测流水线」→ 节点链 `input(选题) → skill:academic-research-suite(定框架) → skill:literature-survey-skill(找空白) → skill:paper-spine(验论证) → skill:nature-reviewer(模拟审) → output(产出)`
- **搭配技能**：上述 4 个技能节点（全部来自技能库，非临时提示词）
- **验证标准**：验论证节点必须显式给出「成立 / 不成立」判断并列断裂点；模拟审必须给审稿结论；**任一节点可 `scope=<node_key>` 单独重跑**，上游结果保留、下游随之更新；全程写 `canvas_node_outputs`（含耗时、状态、上游输入）
- **产物**：候选研究问题表、领域脉络与 Related Work 提纲、逻辑链诊断、模拟审稿 Summary、汇总产出节点

> 这条最贴近 S1 的「执行智能体 + 独立评审智能体」：验论证和模拟审是独立于生成节点的评审节点，且真实给出过**否定结论**（见第 3 节），不是自我确认。

### WF-05 实验执行 → 结果图表 → 结论 · 数据与分析（已有）

- **输入参数**：`实验 id`、`结果数据`、`图表类型`
- **提示预览**：`基于 {实验} 的真实跑批结果生成图表，并只依据图中数据写结论；缺数据处明确标注，不补写数字。`
- **执行路径**：`/experiments` Agent 对话 → `POST /experiments/{id}/chart` → `ResultChart.tsx` → 结论回填
- **搭配技能**：科研数据绘图、`academic-research-suite`
- **验证标准**：图表必须来自真实实验结果端点；不得手写/编造数值；结论与图表不一致时以图表为准
- **产物**：结果图表 + 结论 + 实验状态流转

### WF-06 成文与投稿门禁 · 学术写作（已有）

- **输入参数**：`目标章节`、`目标字数`、`当前阻塞`
- **提示预览**：`按 7 阶段推进：选题定位 → 实验设计与跑批 → 数据整理与图表 → 正文写作 → 内部修改 → 投稿 → 返修。每阶段记录 blocker 与 next_action。`
- **执行路径**：`paper_stages`（7 阶段）+ `paper_sections`（7 章节，word_count / target_words）+ 阻塞 >3 天红警
- **搭配技能**：`paper-spine`、`nature-reviewer`、期刊模板类技能
- **验证标准**：前一阶段 `done` 才推进下一阶段；存在 `blocker` 时不得把该阶段标 `done`；章节字数对齐 `target_words` 才算完成
- **产物**：章节草稿、阶段看板、阻塞与下一步动作留痕

### 分类建议（参照 S1 Categories）

`文献与研究 · 选题与规划 · 实验设计 · 数据与分析 · 学术写作 · 可视化与展示 · 复盘与节奏`。不追求 300+，先把上面 6 条打磨成「可反复执行、可追踪、可复现」的样板。

## 3. 成果案例：LLM 驱动的 Python 单元测试生成 —— 从检索到模拟评审

> 案例格式参照 S1 `#cases` 卡片：领域标签 / 周期 / 轮次 / 标题 / 摘要 / 关键结果 / 执行过程 / 产物 / 会话。
> **全部数字来自本机数据库真实记录**，未做任何修饰或补写。

**领域**：软件工程 · 自动化测试 / AI for SE
**周期**：2026-09-20 → 2026-11-11（库内首次到最近一次 LLM 调用）
**轮次**：2 个调研会话、1 次全链路画布运行、2 次单节点回退重跑、1 个对比实验在跑
**模型调用**：242 次（deepseek，全部有 `llm_usage` 留痕）

### 标题

**LLM 驱动的 Python 单元测试生成：研究现状、评测可信度断层与论证链审查**

### 摘要

围绕「AI 能否生成有用的单元测试」这一方向，用工作台完成了一次从真实文献检索到独立评审的闭环：深度检索经 OpenAlex 拉取并入库带 DOI 的实证与评测文献，生成带引用的研究报告，提炼出「评测可信度缺口 / 方法-评测闭环缺失 / 工业有效性证据薄弱」等研究空白；在此基础上沉淀 5 个带四维评分的创新点，建立 1 个对比实验；再用 4 节点论文流水线跑出候选研究问题、领域脉络、逻辑链诊断与模拟审稿意见。最终**评审节点给出否定判断：论证链不成立**，并明确列出动机、方法、结果之间的断裂点，使研究停在可回退重跑的状态，而不是把未经验证的框架当成结论交付。

### 执行过程留痕（时间线，均取自库内时间戳）

1. **2026-09-20** 建立画布「AI生成单测流水线」等 4 张相关画布（`canvases` id 7/8/9/10），首次 LLM 调用开始留痕。
2. **2026-09-22** 创建对比实验「agent生成python单元测试的对比试验」，写入假设 `agent>coverup`。
3. **2026-11-07 15:59** 开调研会话 id 2；**16:16** 深度检索返回结论与 8 篇引用（耗时 9.3s）；**16:17–16:45** 连续 3 次「报告撰写」，产出带引用报告。
4. **2026-11-07 20:56:36–20:57:42** 画布 8 全链路 run 23：定框架 → 找空白 → 验论证 → 模拟审，6 节点全部 done，各节点耗时 13.8–20.6s，逐节点写入 `input_text`/`output_text`。
5. **2026-11-07 20:59 / 21:36** 单独重跑 `n4`、`n2`，验证「回退到指定节点重跑」；**2026-11-10 00:00** 一次全链路运行被取消（run 26），状态如实记为 `cancelled`。
6. **2026-11-09 19:03** 第二个调研会话 id 6 深度检索（耗时 14.5s），得到更聚焦的结论：「可行性验证 → 评测反思」的转向，以及覆盖率 / 变异杀伤 / 真实缺陷检出三者一致性缺失。
7. **截至 2026-11-11 17:14** 累计 242 次 LLM 调用；论文阶段停在「数据整理与图表」阻塞。

### 独立评审给出的结论（不粉饰）

- **验论证节点**：「这条论证链目前不成立」——动机诉诸「覆盖率与可执行性不足」，方法却押注「变异杀伤在线反馈 + 断言假阳性度量」，两者不是同一个痛点，存在「换个方法也能解决」的断裂。
- **模拟审节点**：判定稿件处于「框架 + 初步结果」阶段，动机、方法、结果、结论四段之间尚未建立可检验的因果对应。
- **防幻觉留痕**：找空白节点明确写出「凡涉及具体论文标题、作者、年份、精确数字之处，我一律不编造……没把握的明确标注『需检索验证』」，并把上游框架里的假设数值标注为实验设计目标而非文献结论。

> 这两条是案例最值得展示的部分：S1 说「执行智能体与评审智能体相互独立，减少自我确认带来的错误」，我们真实跑出来的正是一次**被评审拦下**的研究，而不是一份自我表扬的总结。
