# 科研工作台：功能盘点、重要性分级与 UI 重组方案

- 日期：2026-11-08
- 范围：`growth-workbench/web/src`（约 17,418 行 TSX，48 个 tsx 文件）＋ `growth-workbench/server/routers`（约 200 个端点）
- 性质：**静态代码盘点 + 设计判断**，不是运行数据。项目目前没有埋点/使用日志，所以「重要程度」是按下面第 3 节的显式判据评分得出的设计结论，不是按真实点击频次统计。若要按实际使用频次校准，见 P3。
- 本次未修改任何源码、数据或逻辑；所有定位均给出文件与函数/标识符，行号仅对我亲自通读过的文件标注。

---

## 0. 结论先行

1. 全站功能不是少了，而是**层级与命名错了**：最能打的能力（画布编排、文献关联图、深度检索、课题四阶段门禁）平均埋在 2～4 层之下；而统计卡、录入表单、纯外链站点网格占据了一级入口和首屏。
2. 根因不是视觉，是信息架构：导航按「输入→执行→复盘→激励」的**流程步骤**分组，但三个「工作台」（课题 / 画布 / 调研）其实是做科研的地方，被错分进「输入」；激励和纯外链站点反而各占一个顶级组。
3. 最严重的一致性问题：**「对话工作流」一名三义**，`/research`、`/chat`、`/canvas` 三套后端互不相通，却被双层页签（路由级 `WorkflowTabs` 叠在 state 级 `ChatTabs` 上）绑在一起；`tab` 持久化 + `initialTab` 强改导致 URL 与界面可以不一致。
4. 同一动作平均有 3～4 个入口：文献导入 4 条、设置 3 个入口、退出登录 3 处、导出 5 套、运行 3 处、「技能」4 种含义、承诺 4 处展示。
5. 建议重组为三层：**工作台（3）→ 研究资产（4）→ 节奏与工具（收纳）**，并把「每个模块首屏只放一张招牌卡」作为硬规则。
6. 落地分 P0（只动导航层，当天可验）、P1（IA + 首屏）、P2（合并与联动）、P3（埋点校准）四期；**P0 不改任何后端、不动设计令牌与 UI 原语**。

## 2. 重要性判据（显式定义）

每条功能打三个 0～2 分，**总分 = P + C + R**：

- **P 产出资产**：2 = 直接产出可复用科研资产（文献条目、结构化实验结论、带引用报告、稿件章节）；1 = 只产出过程记录/中间态；0 = 不产出。
- **C 下游消费**：2 = 产出被 ≥2 个模块当作输入数据读取，或驱动跨页告警 / 自动汇总；1 = 被 1 个模块当作输入读取；0 = 仅被展示 / 无下游。
- **R 不可替代**：2 = 外部通用工具无法整体替代（本工作台独有链路）；1 = 可部分替代；0 = 浏览器书签/通用工具即可完成。

判据得分 = P+C+R（0～6），**只用于档内排序，不直接决定档位**。C 的口径收紧为「产出被别的模块当作输入数据读取，或驱动自动告警 / 汇总」；单纯被别处渲染展示的数字卡记 C=0。

档位按功能性质定义（不用分数硬映射，避免凑分）：
- **S 主线引擎**：不可替代的资产生产链路；单点失效会让主线断裂。
- **A 主线关键环节**：产出资产或有明确下游消费的差异化能力，但可被部分替代或消费面窄。
- **B 辅助 / 基础设施**：不产出资产，只提升效率、可读性、节律或运维可靠性。
- **C 装饰 / 低频 / 半成品**：与科研产出无因果，或一次性、或已完成但未启用。
- **S\* 依赖型**：P=0 但为单点故障源，单列、不参与主线排序。

评分依据为第 1 节的代码位置（是否落库、是否被别的页面读、是否有外部等价物），**不是使用频次**；所有分数均为设计判断，不是实测数据。汇总卡、备份、热力图等边界条目的 C 取保守值（0～1），±1 的口径差异不改变档位与处置结论。
